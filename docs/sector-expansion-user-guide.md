# 扇区扩容工单使用说明

## 适用场景

已安装、已开通、维护中的三扇区站点扩容到六扇区时，使用「扇区扩容」工单。

未安装、未开通的站点不需要创建扇区扩容工单，直接在站点规划里导入或编辑六扇区 LLD。

## 操作原则

已开通站点不要直接修改当前规划。先创建「扇区扩容」工单，上传完整目标 LLD，由系统在扩容完成后自动切换规划。

这样做的原因是：扩容施工前，现网实际仍是原三扇区。如果提前把当前规划改成六扇区，OMC 和检查流程会把尚未安装的新扇区判断为异常，影响审核和站点状态判断。

## 一、准备目标 LLD

1. 准备一份扩容后的完整 LLD。
2. LLD 里必须包含原有 3 个扇区，也包含新增扇区。
3. 原有小区不要修改关键字段，例如 `local_cell_id`、`PCI`、频点、带宽、`ECI/NCI` 等。
4. 新增扇区要使用新的设备槽位和小区配置。

注意：不要先去修改站点当前规划。系统会在扩容完成后自动合并目标 LLD。

## 二、创建扇区扩容工单

1. 进入 Web 管理端。
2. 打开「工单管理」。
3. 点击「新建工单」。
4. 工单类型选择「扇区扩容」。
5. 选择要扩容的站点。
6. 选择扩容使用的检查模板。
7. 上传目标 LLD。
8. 查看系统自动预览的信息：
   - 当前扇区数
   - 目标扇区数
   - 新增设备槽位
   - 新增小区数量
9. 确认无误后提交工单。

如果上传失败，通常是以下原因：

- 该站点没有当前规划。
- 该站点已有未完成的扇区扩容工单。
- 目标 LLD 删除了原有小区。
- 目标 LLD 修改了原有小区关键字段。
- 目标 LLD 没有识别出新增槽位。

## 三、施工人员执行工单

1. 施工人员在移动端查看「扇区扩容」工单。
2. 接受工单。
3. 按系统生成的检查项安装新增设备。
4. 对新增设备扫码绑定 SN。
5. 完成现场检查并提交。

系统只会生成新增设备和新增槽位相关的检查项，不会要求施工人员重新检查原有三扇区。

## 四、后台审核与 OMC 确认

1. 审核人员进入工单详情。
2. 查看新增槽位的设备绑定和 OMC 状态。
3. 审核通过后，工单进入 OMC 激活确认阶段。
4. 系统只检查新增槽位是否在 OMC 上激活，不会用六扇区规划误判原有站点。
5. 当新增槽位全部曾经激活后，系统自动完成扩容工单。

如果 OMC 数据延迟或接口没有及时同步，可以在工单里使用手动 OMC 确认。手动确认只能确认本次扩容新增槽位对应的 SN。

## 五、扩容完成后的系统行为

扩容工单完成后，系统会自动把目标 LLD 合并为站点当前规划。

阶段变化如下：

- 扩容施工前：当前规划仍是原三扇区，避免误报。
- 扩容施工中：工单只跟踪新增扇区。
- 扩容完成后：当前规划变成六扇区。

## 常见问题

### 未安装站点是否需要创建扇区扩容工单？

不需要。未安装站点没有现网三扇区状态需要保护，直接导入或编辑六扇区 LLD 即可。

### 目标 LLD 是否只上传新增三扇区？

不建议。目标 LLD 应该是扩容完成后的完整规划，包含原有扇区和新增扇区。系统会自动识别新增槽位。

### 原有三扇区的信息能否顺手修改？

不能修改关键字段。扇区扩容解决的是新增扇区上线，不是原有小区重规划。如果确实需要调整原有小区配置，应先确认业务流程，再走对应的规划变更方式。

### 为什么工单完成前不直接修改当前规划？

因为当前规划会影响 OMC 校验和站点状态判断。提前改成六扇区会让系统认为新增槽位已经应该存在，导致施工前或施工中出现误报。
